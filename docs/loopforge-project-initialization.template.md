# LoopForge 项目初始化模板

项目负责人初始化时填写第 1 至 3 节。公共规范在平台能力资产库维护，项目记录实际订阅的版本。每次启动需求时填写第 4 节，并用第 5 节检查本次交付条件。

## 1. 项目与交付范围

- 项目名称、标识、负责人：
- 系统类型：管理后台 / 用户端 Web / 微信小程序 / 纯后端 / 其他
- 交付端：Vue Web / 微信小程序 / 后端，可多选
- SOP 名称及版本：
- 默认执行环境：Docker / 本地 / 远程执行机
- 默认并行上限：____。每次需求启动可调整，任务数量按依赖关系拆分。
- 允许部署的环境：____。WMS 仅允许交付到测试环境。
- 项目资料归档仓库及需求编号来源：

## 2. 规范与角色订阅

每项填写资产名称、版本和实际订阅角色。有项目例外时注明原因和适用范围。按系统类型和需求范围加载对应规范。

| 规范 | 默认订阅角色 | 需要准备 |
| --- | --- | --- |
| 产品设计 | 产品经理 | 用户与目标、范围、业务规则、权限矩阵、异常场景、验收标准 |
| UI 与交互 | UI 设计师 | 管理后台参考页、导航、列表筛选、表单、权限态与反馈。小程序参考移动导航、授权、触控与异常状态。明确必须点通的操作 |
| Vue 前端 | 全栈开发、前端审核 | Vue/TS 版本、组件库、目录、路由、权限、接口联调、构建和自测命令、可参考页面 |
| 小程序前端 | 全栈开发、前端审核 | 微信原生 / uni-app / Taro、基础库、分包、域名、授权、预览及真机验证 |
| 后端与接口 | 技术方案、全栈开发、后端审核 | 框架和版本、分层、接口契约、认证授权、事务、幂等、构建与自测命令 |
| 数据库 | DBA、全栈开发 | 引擎与版本、DDL、迁移、测试数据、兼容性与回滚验证 |
| 测试与缺陷 | 测试、全栈开发 | 验收及回归用例、测试账号角色、缺陷分级、返工与复测证据 |
| 代码交付与部署 | 开发、审核、运维 | 分支策略、PR/MR 目标、版本标识、健康检查、回滚和验收证据 |

正式产物按需求编号归档：

- 产品需求：`docs/产品需求/<需求编号>/product.md`
- 交互说明：`docs/ui交互/<需求编号>/ui-design.md`
- 可点击原型：`docs/原型/<需求编号>/index.html`
- 纯后端需求在产品阶段只交需求正文。技术方案、自测与验收仍按 SOP 交付。

## 3. 项目环境

每个服务填一行，未配置项标记「缺项」，无需使用的项目标记「不适用」。

| 服务、类型 | 绑定仓库、工作区路径 | 基线分支、PR/MR 目标分支 | 构建和自测命令 | CI Job、实际拉取仓库、部署分支、参数 | 验收入口、健康及版本查询地址 | 凭据引用 |
| --- | --- | --- | --- | --- | --- | --- |
| ____ | ____ | ____ | ____ | ____ | ____ | ____ |

- **Git 与 CI**：合并责任方、所需权限、实际部署单元、构建结果和日志查询方式、重复部署识别方式。
- **测试数据库**：引擎版本、实例、库或 Schema、迁移执行方、允许操作、运行及迁移凭据引用、测试数据与清理方式。
- **测试应用**：可访问的入口、测试账号角色、登录及初始账号提供方式、内网/VPN、隔离方式、恢复负责人。
- **外部依赖**：内网镜像与包仓库、第三方服务、JDK / Maven / Node 等所需版本、容器执行能力。需要 Nacos 时填写测试 namespace、group、dataId 和凭据引用。
- **回滚**：部署版本识别方式、回滚目标和责任人。
- 密码、Token、SSH 私钥放在安全凭据配置中。模板、规则正文和产物只记录引用名。

## 5. 启动前预检与审批

从本次实际执行环境检查，每项登记「通过 / 缺项 / 不适用」和核验依据。

- **每次必查**：需求编号、服务范围、规范可用性、仓库读取、目标分支、工具链和依赖源。
- **部署时检查**：CI 认证、Job 和 SCM/分支/参数配置、所需权限、测试地址与隔离方式。预检阶段只读，实际构建和部署留给部署节点。
- **数据库变更时检查**：测试实例连通、引擎及版本、Schema、迁移权限、执行方和测试数据准备情况。
- **需要原型时检查**：系统类型与参考页面已选定，执行环境可打开原型并验证关键交互。
- **预检结果**：缺项按服务合并成一张清单，注明负责人和验证方法。补齐后只重查预检。通过后将核验结果传给技术、DB 和测试角色。
- **正式业务审批**：第一道审核产品与适用原型，第二道审核技术、数据库与测试方案。子节点把可随方案决定的问题汇总到对应总审。遇到必须解决的未知条件，列出具体阻塞项。
- **后续验收**：专项审核、开发自测、测试部署、缺陷返工与复测按 SOP 执行，记录实际版本和测试结果。
