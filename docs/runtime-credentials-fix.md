# 运行凭据与子流程上下文修复

## Codex 工具命令继承已绑定凭据

Codex 父进程已经收到项目凭据和 Git helper 环境，但默认 `shell_environment_policy.inherit="core"` 不会把这些变量传给工具子进程，导致工具命令认证失败。

在最终命令装配时生成变量名称白名单，仅放行基础环境、当前命令绑定的 Git helper/relay/SSH 配置以及显式选中的项目凭据。变量值通过进程环境传递，不写入命令参数、配置文件或提示词；模型 API Key 和未选中的宿主令牌不在白名单内。续跑参数与 prompt/stdio 的位置保持不变，没有绑定凭据的 Codex 和其他 CLI 沿用原行为。

对应实现位于 `internal/runtime/provider_codex.go` 和 `project_credentials.go`。回归用例覆盖 HTTP Git、SSH、项目凭据、模型 Key 隔离、续跑参数和无绑定情况。

## 父流程人工补充传入子流程

父运行在人审或重试时保存的 `HumanContext` 原先没有传入子流程输入，子角色可能重复询问已经澄清的条件。`sopChildInput` 现在将父运行最新人工补充拼入输入；进一步嵌套时沿输入继续传递，不依赖工作区中的历史上下文文件。

对应实现位于 `internal/engine/sop_node.go`，引擎回归用例覆盖人工补充、嵌套传递与既有产物交接。

人工补充应写明适用阶段，避免临时排障限制进入后续开发阶段后继续生效。需要角色执行工作时，应补充上下文并重跑当前节点；直接批准完成节点不能替代缺失的执行。

## 后续同步要求

合并上游时分别核对工具环境策略与子流程输入构建。如果上游提供等价实现，保留相同场景的回归用例；需求到对话的上下文交接不等于父流程人工补充传递。具体环境运行记录与业务产物不纳入仓库。
