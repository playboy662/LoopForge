# 共享 Java / Node 执行环境

此目录保存通过 LoopForge 环境资产页面维护的通用工具链源文件，不保存业务仓库、服务器地址或凭据。

## 资产关系

| 载体 | 标识 | 内容 |
| --- | --- | --- |
| Dockerfile | shared-java21-node22 | Java 21、Maven 3.9.11、Node 22、Python 3、MySQL 客户端、Codex 0.171.0 |
| Docker 沙箱 | shared-java21-node22-docker | 引用上述 Dockerfile，工作区可写，环境变量为空 |
| 安装脚本 | shared-docker-compose-tools | 在 PREFIX/bin 安装 loopforge-docker-check，运行时检查 daemon、Compose、Git 和 Python |
| 原生沙箱 | shared-docker-compose-native | 引用安装脚本，供运维及 Docker 查询门禁执行 |
| SOP | 按阶段选择沙箱 | 沙箱定义随新运行冻结，已有运行不被环境修改影响 |

四项资产归属能力资产项目并共享给其他项目。已通过页面创建并核对引用；镜像实际构建与运行验证须单独记录，创建成功不等于验收通过。

## 对照平台实现的使用方式

- Dockerfile 作为数据库中的构建定义，由沙箱初始化构建；不把业务仓库目录或宿主机的临时镜像名当成资产正文。
- Docker 驱动使用 Dockerfile；环境安装脚本用于 local/native 进程沙箱。不要给 Docker 沙箱配置一个实际上不会执行的安装脚本。
- 平台自带每运行的 Chromium/Playwright 浏览器；工具链镜像不另装一份浏览器来替代平台交互和证据。
- 启动任务前选好环境。换 Dockerfile/沙箱只影响新运行，不刷新旧运行去冒充使用了新环境。
- 模型凭据仍使用任务责任人在平台配置的 Codex Key。Dockerfile、沙箱变量和共享技能均不存储 Key。
- 应用进程、数据库服务、数据卷和验收入口属于测试运行的生命周期，需要与工具链镜像区分。自带静态前端预览不能代替后端、数据库和授权接口的真实验证。
- 当前平台 Docker 沙箱不挂宿主 Docker socket。需要编排独立应用容器时，由具有 Docker 能力的执行机承担；不要在通用开发镜像中启动 Docker daemon 或假定存在宿主 socket。

依据：README.md 的 Sandboxes、docs/deployment.md 的 Docker sandboxes、docs/api/registry.md 的环境资产接口，以及 internal/runtime/sandbox_environment.go。后续与官方合并时先核对这些行为是否改变。

## 批准方案与执行环境的交接修复

方案设计可以登记后续执行条件；批准设计不等于仓库权限、测试库、凭据交接和测试入口已经验证。原自定义流程直接要求设计报告的 `missing=[]`，导致通过方案人审后仍必然失败。修复保留批准设计、摘要和待办原文，用独立的 `executionReadiness` 记录实际前置条件，由冻结与研发轮次节点传递给下游。

`wms-execution-readiness.py` 是该修复的运行脚本源码，仅供已经批准双仓库范围的 WMS 原生门禁使用，不作为平台启动逻辑或全局默认资产。它验证本轮 Git 身份和只读推送预检、开发工具链到测试入口的实际 HTTP 链路、MySQL 隔离测试库、受限凭据引用、可恢复的合并记录及备份恢复能力。Git 认证仅作用于本次进程，不修改个人或全局配置。私密文件留在本 flow 工作区，报告只包含文件引用。

已批准设计中的未知待办仍拒绝放行；部署后才能产生的实际版本、健康和 QA 证据由对应下游门禁继续核验。测试库与运行期交付资源只按 flow 清理，不运行全局清理。环境预检通过不能替代应用构建、实际部署或业务验收。

真实验证：修复后的门禁在 2026-11-21 完成全部八项执行前置核验并退出 0；冻结和研发轮次交接随后成功，开发角色读取交接后再次查到 MySQL 8.4.11，开始实现与自测。首次预检还发现原生 Git 缺少命令级认证和官方镜像下载超时，分别改为进程级认证及按同一官方摘要从显式镜像缓存获取。原有工具链缓存、个人凭据和全局配置均未修改。完整业务部署与 QA 另行验收。

## 无 Git 项目的 Compose 发布路径预检

`verify-compose-route.py` 在原生 Compose 沙箱运行，接收 flow 标识、候选宿主端口和已有工具链镜像。脚本用临时 HTTP 标记验证宿主入口与独立工具链容器到 `host.docker.internal` 的实际访问，再清理本次 Compose 项目并核验端口释放；macOS 的 TIME_WAIT 不算仍在监听。它只确认发布路径能力，业务应用的健康、版本和验收仍由部署及 QA 节点实测，部署前也须重新检查端口。
