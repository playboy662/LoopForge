# 平台后端开发规范

适用于架构、后端、数据库、评审和测试角色。根据 PZH 后端与接口规范提炼。
通用条款适用于各语言；Java/Spring、Feign、MyBatis-Plus 和 C12 条款按下面的
技术栈条件生效。用户和项目明确的规范优先，不据此迁移目标项目的技术栈。

## 分层、契约与基础能力

1. 接口层负责协议、校验和响应，业务层负责业务规则、编排与事务边界，数据层负责持久化。遵循项目既有领域和模块归属，不在入口、Controller 或通用基础类中堆业务逻辑，不建立循环依赖。
2. 对外契约与内部实现分离，不把 Entity、DAO、持久化 Wrapper 或框架上下文作为长期接口协议。参数较多时按业务语义组织明确类型，不使用无关字段混装的 Map 逃避建模。
3. 复用已批准的基础库和稳定公共能力。基础库不反向依赖业务服务；可选组件提供启用条件，未配置时不隐式连接外部资源或启动消费者、调度器。
4. 请求与响应明确路径、方法、字段类型、必填、长度、范围、枚举、精度、单位、鉴权与失败场景。同步实现、接口文档、调用契约和前端约束；变更时说明兼容性，删除前确认调用方已迁移。
5. 按目标项目既有约定组织 SQL、接口响应和异常码，不将 POST、某种响应包装类、ORM 或目录结构作为所有语言的默认要求。

## 一致性、缓存与消息

1. 写操作、多表修改、状态流转及库存、余额等敏感动作明确事务和并发控制。异常正确传播并触发预期回滚，不能吞异常后返回成功。
2. 事务与消息发送、远程调用、异步任务之间明确提交顺序、重试、补偿和失败状态，不假定本地事务能保证跨系统原子性。消息消费、任务重试和写接口按业务需要保证幂等。
3. 新增 Redis 缓存读路径必须考虑穿透：确认源数据不存在时写入带明确空值语义的占位缓存，TTL 短于正常数据；读取时区分空值占位和未命中，避免持续回源。明确更新、删除、过期及并发失效策略。
4. 复用项目消息、事件、锁、限流、编号和任务抽象，不因底层中间件不同复制两套业务逻辑。消费失败必须可观察，不能伪装已处理成功。

## 数据、SQL 与权限

1. 新建表、所有字段、主键和公共审计字段都必须有注释。除用户明确允许 NULL 外，默认 NOT NULL，并按语义设置默认值：数值 0、字符串 ''、布尔或 tinyint 0、tenancy 1、时间 current_timestamp。
2. 可选值使用有定义的哨兵表达空语义，并在接口、缓存、消息和查询边界做归一化。区分缺失、不修改、真实零值和空值，不把哨兵误当业务数据。
3. 查询参数化；动态筛选和排序使用白名单。按真实 scope 和查询补齐索引，避免 N+1、无界分页及逐行替代集合操作。唯一索引必须先核对业务约束和历史数据。
4. 复用已有数据访问框架，复杂 SQL 按项目约定集中组织，禁止为局部方便引入第二套 ORM。批量与原生 SQL 保留租户、权限、审计字段、并发控制、影响行数校验及事务语义。
5. 租户、公司、权限和审计身份优先取可信上下文；服务端核验访问范围，不信任前端任意传入的身份字段。创建期字段不能在普通更新中被覆盖，业务权限与租户隔离分开建模。
6. 精确金额和数量使用数据库定点类型及语言对应的十进制能力，不用二进制浮点承载精确业务值。Long 等超出 JavaScript 安全整数范围的值按字符串契约交付；时间格式、时区、精度和舍入规则在接口中写清。
7. 使用稳定业务错误码，区分业务失败与系统异常。远程失败保留有意义的原始错误语义，不包装成成功数据；响应不泄露堆栈、SQL、密钥或内部部署信息。日志保留必要业务定位信息并脱敏。

## 技术栈条件

- **Java/Spring 与 Feign：** 采用 Feign 跨服务调用时，接口必须定义在被调用方对应的 `*-api` 模块，调用方不得自行声明其他服务的 FeignClient。契约、Controller、DTO 与文档保持一致。Spring 写库业务方法显式声明适用的 `@Transactional`，检查代理、自调用、异常类型与回滚条件，不依赖旧全局事务表达式自动生效。
- **MyBatis-Plus：** 优先复用现有 BaseMapper、Service 和类型安全 Wrapper。能由通用 CRUD 表达时不新增冗余 Mapper/XML；联表、投影、聚合和批量复杂 SQL 保留项目约定的自定义实现。不要将一个集合操作拆成逐条读写；不要把 Wrapper 暴露为 HTTP 或远程契约。
- **PZH/C12：** `*-api` 放契约，`*-biz` 放业务实现，`*-web` 放启动装配；Condition、PageCondition、Item、Query 沿用项目定义。持久化和公共字段复用对应 Core 基类，按现有 JPA、MyBatis-Plus 或 sqlExecutor 基线实现，不跨框架套用。方法超过三个参数时按业务语义封装，分页参数也计入数量，参数实体不因此变成数据库实体。
- **PZH/C12 基础库：** `c12-core` 只维护 2.0 分支，不创建 test 分支、不参与业务仓库 test 合并。只有任务已授权访问基础库时才读取或修改对应目录；按需复用 Core 的缓存、MQ、Event、Message、任务、文件和编号能力。组件、协议及异常类型以目标项目当前代码为准，不能照搬旧版本清单。
- **接口文档工具：** Java/Spring 项目按已采用的 OpenAPI 约定维护接口与模型注解；项目使用 Apifox 时同步交付到 Apifox，其他项目使用自身已配置的文档和契约管理工具。

## 验证

接口变更核对调用方，数据修改核对事务、约束和权限，缓存验证命中、未命中与空值占位，消息验证重复与失败恢复。执行项目真实构建和相关测试，提交 SQL 或变更说明时交代影响、执行顺序和回退方案；未获授权不直接修改真实业务数据库。
