# 平台前端开发规范

适用于 UI、前端、评审和测试角色。根据 PZH 前端规范和 CRUD 实践提炼。
通用条款适用于各前端技术栈；Vue、Pinia、C12 和任务中心条款仅在项目已采用
对应能力时生效。用户和项目明确的设计及工程规范优先。

## 结构与复用

1. 先读取目标项目设计规范、真实组件和相似页面，确认接口及字段，再实施。沿用现有布局、视觉语言、路由、状态管理和目录结构，不为使用本规范改换框架。
2. API 请求集中到项目请求层，复用登录、权限和异常处理；页面不散写服务地址或绕过请求封装。同一接口维护一份定义，类型、请求方法和字段说明按业务域组织。
3. 查询条件、列表、编辑、详情和页面私有组件职责清楚。新增、编辑、查看模式明确；复杂页面按实际职责拆分，不堆超长单文件，也不为了形式拆出没有价值的小文件。
4. 复用现有查询、表格、弹窗、选择器、上传及业务组件；稳定管理表格 key、分页、排序和查询条件。不复制整页旧代码后无边界改写，不在不同页面重复造基础组件。

## 接口、精度与表单

1. 使用真实后端字段，明确请求、列表展示、编辑入参和详情类型，避免大面积 any。字段必填、长度、枚举、数值范围、精度、单位和前后端约束一致，不为兼容旧示例创造不存在的字段。
2. 后端 Long ID 和其他可能超出 JavaScript 安全整数范围的值按字符串处理，不能转换成 number。金额、数量、重量等精确小数遵循字符串或高精度契约，避免浮点运算破坏业务精度。
3. 日期时间、时区、单位和舍入遵循接口约定，不无声改变日期格式或把字符串日期变成秒、毫秒时间戳再提交。状态判断使用稳定 code，不根据中文名称或错误消息分支。
4. 表单保存前校验必填、格式、长度和范围，校验规则与后端契约一致。保存、批量操作和重复提交有明确防重或 loading 状态；服务端仍负责最终校验和幂等。

## 交互、状态与权限

1. 覆盖加载、空态、错误、权限不足、成功反馈和失败重试；处理重复点击、请求竞态、旧响应覆盖及分页边界。沿用已有响应式和可访问性约定，关键流程可以实际操作验证。
2. 全局共享状态放项目状态层，页面临时显隐和草稿状态在局部收口。退出页面或销毁组件时清理监听、计时器、订阅与 SSE/WebSocket 等连接，重连与异常提示沿用已有封装。
3. 路由、菜单、按钮权限与后端权限码一致；前端隐藏按钮不能替代服务端鉴权。禁止绕过权限体系或把身份和权限判断散落为不可追踪的页面常量。
4. 复用国际化资源、主题变量、设计 token 和公共样式。局部样式在局部收口，避免无边界全局覆盖；显示文案、单位、字典颜色与状态语义保持一致。
5. 上传、下载、导入导出沿用现有协议，明确任务状态、进度、失败反馈及访问权限。大数据量、批量和大文件操作不假定同步返回，按真实后端接口使用异步流程。

## 技术栈条件

- **Vue 项目：** 已采用 Vue 3、TypeScript、Composition API 和 script setup 时沿用既有约定；目录、组件命名、样式预处理和别名以项目为准。Pinia、Vue Router、vue-i18n、Element Plus 只在项目已经采用时使用，不强加给 React、其他框架或历史工程。
- **PZH/C12：** 优先复用目标项目 C12 组件及当前授权范围内可读的 CRUD 示例。查询、表格、弹窗和选择器的真实名称、属性与事件以当前实现为准；旧手册名称冲突时核对现有组件，不伪造兼容字段。API 与 model、页面及私有组件按目标工程约定组织。
- **项目使用 Apifox：** 接口字段、校验与示例以已确认的交付契约为准，发现与后端实际实现不一致时先澄清，不能盲目复制任一旧版本。其他项目使用自身的契约管理工具。
- **项目使用任务中心：** 导出、批量下载等按创建任务、查询状态和完成后下载的实际链路实现；普通同步下载仍按真实接口处理，不为所有项目强制引入任务中心。

## 验证与交付

发生代码改动时执行项目约定的构建、启动和必要静态检查。公共组件改动进行构建及代表页面验证；请求链路验证真实页面，覆盖查询、分页、保存、权限、校验与异常状态。纯设计或原型任务按约定交付范围验证，不因绑定本规范强制执行代码构建。报告实际命令、退出码、页面证据和未验证范围，不能以只有静态截图代替可运行行为。
