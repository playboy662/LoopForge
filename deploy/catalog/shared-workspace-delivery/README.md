# 无 Git 工作区交付

此目录保存 `deliveryMode=workspace_v1` 的交付协议与门禁源码，供平台能力资产和流程模板引用；不改变平台启动、迁移或 seed 行为。

- `workspace-delivery.md`：共享角色按阶段交接的文件格式、职责与 Docker 验证要求。
- `gate.py`：流程脚本使用的 Python 标准库检查器。初始化节点将其写入本次运行工作区，并提供逻辑节点名到实际节点 ID 的 `nodes.json`。各检查节点调用 `main(stage)`。
- `ledger-generation.md`：通用台账流程的条件扩展，按实体/字段、状态动作、API/页面、事务并发模型驱动 AI 代码生成；通过初始化标记启用，复用原报告字段与两道人审。不是确定性模板生成引擎。

完整流程包含产品与交互原型、产品人审、技术/数据库/测试方案、方案人审、实现、自测命令独立复核、三项独立审核、Docker 部署、QA 与缺陷回流。主流程使用开发工具链沙箱，Docker 部署及实际容器检查使用原生运维子流程。

交付身份由 `flowId`、产品/方案摘要、`roundId` 和源码文件 SHA256 清单确定。门禁生成源码压缩包，核对报告、实际文件、容器标签、健康状态和 HTTP 版本；归档超过当前大小限制时停止交付。应用代码位于 `app/`，报告与检查器位于 `.loopforge-workspace/`，不创建 Git 元数据。

门禁检查交付物、验收覆盖、版本与轮次、源码漂移、独立构建/测试结果及部署证据。已有 10 项隔离检查覆盖工作区身份、方案契约、实际命令执行、源码漂移、Git 元数据拒绝、审核交接及缺陷回流；其中不包含真实业务部署。隔离检查与工具链验收不能替代业务的人工批准、浏览器测试或部署验收。

平台配置通过页面维护。若当前页面没有逐节点产物编辑入口，仅可在确认界面限制后补充对应流程的 `artifactOutputs`，不能借此修改共享角色或其他项目配置。运行和发布继续使用页面，并保留变更记录。
