# 通用台账代码生成

仅当本次运行存在 `.loopforge-workspace/ledger-mode.json` 且 `profile=generic_ledger_v1` 时使用。流程复用共享角色与 `workspace_v1` 报告契约；本文件补充业务方法，不新增报告顶层字段。生成指依据批准模型由 AI 实现代码，不表示平台已有确定性的模板生成器。

## 产品与交互

先确认台账主体、业务记录、使用者、查询条件、可执行动作与范围外功能。为每个动作给出前置状态、输入、成功状态、失败反馈与验收编号；区分主数据和不可被覆盖的业务历史。权限、导入导出、附件、审批、通知、多租户等只在需求明确需要时纳入。

已有产品说明或原型可作为候选输入：核对来源运行、需求、文件 SHA256、版本和适用范围，列出保留内容与缺口，迁移到本次工作区报告。旧 flowId、审批结论和浏览器演示状态不能沿用为本次交付身份。原型的 localStorage 不能证明真实数据库持久化。不得重新设计已确认且适用的内容以扩大需求。

UI 应覆盖列表、搜索筛选、表单、详情/历史、状态动作、空结果、错误恢复及键盘焦点。实际操作可点击原型；明确哪些仅为演示、哪些要到实际应用验证。完成产品包后停在正式产品人审。

## 批准前的方案建模

技术角色在 `technical-plan.md` 增加「台账生成模型」，用可审阅的表格描述：

- 实体与关系：主键、业务编号、字段类型、必填/默认值、长度、可选值、日期/时区、查询和排序语义。
- 页面与 API：列表、筛选、详情、写操作和历史查询，字段到请求、响应、表单及存储的对应关系；分页按数据规模决定。
- 状态与动作：来源状态、目标状态、事务边界、非法转换与错误码；并发执行同一动作时如何保证只有合法操作成功。
- 生成范围与业务实现：可复用的字段映射、表单和列表，以及必须单独实现的状态流转、历史写入、事务和冲突处理。
- 实际前端/后端/数据库及版本、构建测试命令、目录、迁移与部署方式。技术栈来自项目和批准方案，不能因共享环境有 Java/Vue 就强制使用。

数据库角色据此给出建表、约束和必要索引，明确状态更新与业务记录的原子性、并发策略和失败回滚。遵守表/字段注释、NOT NULL、合理默认值要求；SQLite 不支持 COMMENT 子句时，用紧邻字段/表的 SQL 注释保留说明。可选值的哨兵及接口归一化必须写清。演示数据初始化必须幂等且不覆盖已有业务数据；设计持久卷、重启和迁移失败的验证方式，不提前操作数据库。

测试角色按产品验收编号设计实际可执行测试，特别覆盖非法/重复动作、并发竞争、无效输入、错误恢复、历史一致性、初始化幂等及容器重启持久化。权限或导入等仅在产品范围内测试。完整方案通过原有结构门禁和正式方案人审后才能生成应用。

## 实现、独立审核与验收

全栈角色按冻结方案在 `app/` 生成数据访问、API、页面、状态操作、迁移、测试、Dockerfile 和 Compose。先完成可复用 CRUD，再完成业务规则；禁止用通用 CRUD 更新接口绕过状态前置条件。数据库事务/条件更新落实并发控制，不能仅靠按钮禁用或浏览器变量拦截重复动作。业务历史与状态写入一起成功或一起失败。构建及测试须实际执行，记录生成范围与手写业务逻辑，不声称已建设通用生成引擎。

架构审核核对模型、API及业务边界；数据库审核核对约束、事务、并发和初始化；UI审核核对实际页面、反馈和键盘行为。三者只审当前冻结源码，缺陷进入原有返工链，不能修改验收标准。部署使用本流程绑定的共享 Docker 子流程与隔离卷。

独立 QA 对部署后的真实应用执行完整业务路径、重复操作和并发验证；重启本 flow 的容器后再次核对状态与历史，必要时核对数据库。原型测试或开发自测不能替代此步骤。最终按既有协议交付源码归档、模型/方案、Compose、真实验收证据、访问入口、限制及仅针对本 flow 的回收命令。
